# Отчётность по рейсам — этап 1

## Что реализовано

- загрузка CSV через существующий `ManifestParser` и `import_manifest_csv()`;
- объединение файлов по бизнес-ID ведомости (`manifests.trip_number`): повторная загрузка создаёт версию файла, а не второй рейс;
- ручная правка карточки рейса и пассажиров;
- независимые факты `attendance` и `refund_status`;
- стоимость ведомости и наша стоимость без перезаписи исходной цены;
- агенты с несколькими договорами: деньги получает Интерсити Тур или перевозчик;
- раздельные коммерческая, диспетчерская и агентская комиссии;
- наличные по рейсу;
- защищённые файлы рейса и неизменяемые версии расчёта.

## Правила первичного расчёта

- явка / без возврата: обычный расчёт;
- неявка / без возврата / наш договор: база перевозчика — 0, наша выручка сохраняется, прибыль уменьшается на комиссию агента;
- неявка / возврат оформлен: обе стоимости и комиссии в расчёте — 0;
- продажа по прямому договору агента с перевозчиком: коммерческая комиссия — 0%, диспетчерская — по договору (по умолчанию 7%);
- неизвестная явка временно считается явкой, но блок контроля показывает предупреждение;
- явка и оформленный возврат одновременно показываются как противоречие.

## Выкладка

1. Применить `schema14.sql`.
2. Создать защищённое хранилище, доступное пользователю PHP-FPM, и добавить в `/etc/panel.env`:

   `REPORTING_STORAGE_DIR=/var/lib/panel/reporting`

3. Каталог не должен обслуживаться веб-сервером напрямую. Скачивание идёт только через авторизованный маршрут `?p=report_file`.
4. После миграции открыть «Отчётность», загрузить тестовую CSV и проверить ID, число пассажиров и исходные цены до работы на реальном рейсе.

## Осознанно оставлено на следующие этапы

- периоды действия и приоритеты сложных тарифных правил;
- согласование/блокировка финального отчёта и роли;
- месячные реестры и экспорт для перевозчика;
- автоматическая сверка продаж из каналов с пассажирами;
- удаление/архивация файлов и журнал изменений каждого поля.
