# Правило для рассылок: Green API

Перед любой правкой, тестом или выпуском, затрагивающим рассылки, каналы,
проверку получателей, очередь или статусы, сверяем решение с актуальной
документацией провайдера Green API.

Основные ссылки:

- [FAQ Green API для MAX](https://green-api.com/v3/docs/faq/)
- [Как снизить риск блокировки](https://green-api.com/v3/docs/faq/how-to-reduce-risk-of-blocking/)
- [Проверка и хранение chatId](https://green-api.com/v3/docs/faq/identifier-in-max/)
- [SendMessage и внутренняя очередь](https://green-api.com/v3/docs/api/sending/SendMessage/)
- [Статусы исходящих сообщений](https://green-api.com/v3/docs/api/receiving/notifications-format/statuses/OutgoingMessageStatus/)
- [Очереди Green API](https://green-api.com/v3/docs/api/queues/)

Обязательные правила интеграции:

1. Сохранённый `chatId` используем повторно; не вызываем `CheckAccount` перед
   каждой отправкой.
2. `exist=false` не перепроверяем автоматически. Ошибку лимита проверки не
   считаем отсутствием аккаунта.
3. Ответ с `idMessage` означает принятие провайдером, а не доставку.
4. `noAccount`, `delivered` и `read` обрабатываем по webhook и сохраняем
   отдельно.
5. Скорость задаётся настройкой очереди Green API; PHP-запрос не должен держать
   всю кампанию в синхронном цикле.
6. Перед изменением отправки проверяем риск блокировки, STOP-фильтр,
   идемпотентность, повтор запроса и частичный сбой.

Если документация изменилась, обновляем этот документ и только затем меняем
код. Реальные массовые сообщения для тестов не используются.
