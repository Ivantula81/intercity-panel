# Срок входа и возврат к работе

Решение владельца от 25.10.2026, журнал #35 LOG-099.

Сервер допускает защищённые страницы и API только до ближайшего из сроков:
30 минут после активности сотрудника или 12 часов после успешного входа.
Фоновый опрос, просмотр статуса и автоматическое обновление данных не продлевают
доступ. Видимая вкладка сообщает о действиях сотрудника отдельным запросом с CSRF,
не чаще раза в 30 секунд; это также точность учёта активности. Запрос после
истечения срока не может восстановить доступ. Уже принятое фоновое задание
продолжает работать независимо от входа сотрудника.

За две минуты показывается предупреждение. По сроку текущая страница закрывается
экраном входа; сервер независимо отклоняет запросы до вызова бизнес-обработчика.
API возвращает 401 с `auth_required`, страницы направляют на вход. Обычный срок
хранения PHP-сессии и cookie не является сроком авторизации.

Повторный вход на заблокированной странице допускает только прежнюю активную
учётную запись и проверяет пароль. ID сессии, CSRF и начало смены меняются,
предыдущий ID отозван. Другой пользователь должен выйти и войти обычным способом.
Пять неудачных попыток вводят минутную задержку для текущей сессии; это не замена
отдельной защите по аккаунту/IP или MFA.

Несохранённые поля остаются в памяти открытой страницы. После входа их нужно
проверить и при необходимости сохранить; бизнес-запросы автоматически не
повторяются. Закрытие страницы может потерять произвольный несохранённый ввод.
Действие, уже принятое сервером до истечения срока, могло выполниться — его
результат нужно проверить перед ручным повтором.

Существующие зашифрованные снимки рабочего места (включая черновики чатов)
сохраняют срок 7 дней. После тайм-аута сервер оставляет ограниченный контекст
восстановления без прав доступа: только проверенные данные прежнего пользователя
позволяют вернуть ключ. Срок самого снимка проверяется независимо. Обычный вход
тем же пользователем также восстанавливает ключ, пока доступен контекст.
Ручной выход удаляет его, смена пользователя создаёт другую область хранения.
Нельзя гарантировать восстановление после удаления cookie/серверной сессии,
очистки браузера или истечения срока снимка.

Статус сессии не выдаёт ключ шифрования. После повторного входа той же учётной
записью другие вкладки обновляют CSRF и снимают блокировку по новой версии входа.
Смена аккаунта закрывает прежнее рабочее место. Без ответа сервера блокировка
не снимается; неоднозначный ответ входа можно проверить повторным чтением статуса.

При первом выпуске сессии без сроков требуют однократного повторного входа.
Миграций бизнес-данных нет. Для отката возвращается полный предыдущий выпуск;
его прежняя политика входа также возвращается, что нужно учитывать при решении.

Проверки: `php tests/session_policy_test.php`, `node tests/session_ui_test.cjs`
(Playwright/Chrome, локальный PHP с SQLite), `./scripts/preflight.sh` и регрессии
рабочего места, сохранения, ведомостей и отмены уведомлений. Тестовые пользователи,
БД и HTTP-сервер изолированы; внешние отправки не вызываются.
