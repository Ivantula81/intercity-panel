# Инструкция по разделу «Отчётность»

Версия: этап 1, июнь 2026 года.

## Назначение

Раздел собирает данные рейса, пассажиров, финансовые условия и все версии файлов в одной карточке. Основной идентификатор — **ID ведомости** из CSV. Всё, что относится к одному ID, считается одним рейсом.

Рабочий процесс:

`CSV → проверка рейса → явка/возврат → цены и договоры → расчёт → сохранение версии → файлы рейса`

## 1. Подготовка справочника агентов

Откройте «Отчётность» и разверните блок «Справочник агентов и договоров».

| Поле | Что указывать |
|---|---|
| Агент | Понятное название бренда: GoBus, Росбилет, Интерсити Тур |
| Псевдонимы из CSV | Варианты написания через запятую. Они нужны для распознавания колонки «Агент/кассир» |
| Название договора | Например: «Договор с Интерсити Тур» или «Договор ИП Ванюк» |
| Сторона договора | «С нами» — деньги поступают нам; «С перевозчиком» — деньги идут напрямую перевозчику |
| Перевозчик | Заполняется для прямого договора агента с перевозчиком |
| Комиссия агента | Процент агента, удерживаемый из продажи |
| Коммерческая | Для наших продаж обычно 15%; для прямых продаж перевозчика — 0% |
| Диспетчерская | Обычно 7% |
| Расчёт диспетчерской | «Взаимозачёт» уменьшает выплату перевозчику; «Отдельная задолженность» учитывается отдельно |

Один агент может иметь несколько договоров. Если у GoBus есть договор и с нами, и с перевозчиком, создайте две договорные записи. Система не выбирает между ними автоматически — оператор указывает нужный договор у пассажира.

Рекомендуемые начальные настройки:

- наши прямые продажи: сторона «С нами», коммерческая 15%, диспетчерская 7%;
- агент с договором с нами: сторона «С нами», комиссия агента по договору, коммерческая 15%, диспетчерская 7%;
- агент перевозчика: сторона «С перевозчиком», коммерческая 0%, диспетчерская 7%.

## 2. Загрузка CSV

1. Нажмите «Загрузить ведомость».
2. Выберите CSV и нажмите «Загрузить и рассчитать».
3. Проверьте ID, дату, маршрут, перевозчика, автобус и водителей.
4. Сверьте количество пассажиров и исходные цены.

При повторной загрузке файла с тем же ID второй рейс не создаётся. Файл сохраняется как новая версия в «Файлах рейса», а ручные исправления пассажиров не перезаписываются.

## 3. Проверка пассажиров

Для каждого пассажира проверьте ФИО, телефон, маршрут, агента/договор и обе цены.

- **Стоимость ведомости** — согласованная цена, используемая для расчёта с перевозчиком.
- **Наша цена** — фактическая цена продажи. Если поле пустое, используется стоимость ведомости.
- **Явка** — «Явка», «Неявка» или «Не отмечено».
- **Возврат оформлен** — включается только после фактического оформления возврата.

«Не отмечено» временно считается явкой, но окончательный расчёт с такими пассажирами сохранять не рекомендуется.

## 4. Финансовая логика

### Явка, возврата нет

Обычный расчёт. Перевозчику начисляется стоимость ведомости за вычетом применимых комиссий. Разница между нашей ценой и стоимостью ведомости входит в нашу прибыль или убыток.

Пример: ведомость 3 500 ₽, наша цена 4 500 ₽, коммерческая 15%, диспетчерская 7%.

- коммерческая: 525 ₽;
- диспетчерская: 245 ₽;
- к выплате перевозчику: 2 730 ₽;
- наша прибыль до комиссии агента: 1 770 ₽.

### Неявка, возврат не оформлен, договор с нами

Перевозчику — 0 ₽. Наша выручка сохраняется. Прибыль равна нашей цене за вычетом комиссии агента.

### Неявка, возврат оформлен

Стоимость ведомости, наша выручка, комиссия агента и прибыль в расчёте равны 0 ₽.

### Продажа агента перевозчика

Деньги не проходят через нас. Коммерческая комиссия равна 0%. Диспетчерская комиссия рассчитывается по договору и идёт во взаимозачёт либо в отдельную задолженность перевозчика.

Комбинация «Явка + возврат оформлен» считается противоречием и появляется в блоке «Контроль».

## 5. Наличные

Нажмите «Внести наличные», укажите сумму, у кого находятся деньги и комментарий. Запись хранится отдельно от цены билета и не изменяет исходные данные пассажира.

## 6. Файлы рейса

Во вкладке «Файлы рейса» хранятся:

- исходные CSV и их версии;
- рабочая ведомость водителя с ручными пометками;
- документы для водителя и перевозчика;
- расчёты и отчёты.

Файлы лежат в защищённом хранилище и скачиваются только после авторизации в панели.

## 7. Сохранение расчёта

После проверки нажмите «Сохранить расчёт». Создаётся неизменяемая версия, содержащая факты по пассажирам, действовавшие договорные ставки и итоговые суммы. Последующие изменения создают новую версию и не переписывают старую.

## 8. Что проверить тестировщику

1. Загрузка нового CSV создаёт один рейс с корректным ID.
2. Повторная загрузка того же ID не создаёт дубль.
3. Все поля пассажира редактируются и сохраняются после обновления страницы.
4. Добавление и удаление пассажира работают.
5. Проверены четыре сценария: явка; неявка без возврата; неявка с возвратом; продажа агента перевозчика.
6. Переключение договора меняет расчёт.
7. Предупреждения показывают неизвестную явку и противоречия.
8. Наличные сохраняются.
9. Рабочая ведомость появляется во вкладке файлов и скачивается.
10. «Сохранить расчёт» создаёт следующую версию.
11. Экран проверен на компьютере и телефоне.

Для сообщения об ошибке приложите ID рейса, ФИО пассажира, ожидаемую и фактическую сумму, описание действий и скриншот. Не отправляйте CSV с персональными данными в открытые чаты.

## 9. Техническая схема

| Таблица | Назначение |
|---|---|
| `manifests` | Карточка рейса и бизнес-ID ведомости |
| `passengers` | Пассажиры, явка, возврат, договор и две цены |
| `report_agents` | Бренды агентов и псевдонимы |
| `report_agent_contracts` | Сторона договора и ставки комиссий |
| `manifest_files` | Защищённые версионные файлы рейса |
| `manifest_cash_entries` | Наличные по рейсу или пассажиру |
| `manifest_calculations` | Неизменяемые версии правил, фактов и итогов |

Факты (`явка`, `возврат`, цены) хранятся отдельно от правил (проценты и сторона договора). Поэтому будущая смена тарифа не изменяет уже сохранённый расчёт.

## Ограничения этапа 1

Пока не реализованы месячный реестр и экспорт перевозчику, периоды действия сложных тарифов, финальное согласование по ролям, автоматическая сверка продаж из каналов и журнал каждого изменения поля.
