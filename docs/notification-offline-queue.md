# Уведомления при недоступном провайдере

Подготовка и подтверждение уведомлений сохраняют задания локально без сетевого
опроса Green API. Настроенный поддерживаемый канал можно выбрать независимо от
доступности провайдера; наличие адреса получателя и отписка проверяются по
сохранённым данным. Неизвестный адрес Telegram не считается известным.

Каждая доставка получает срок: сохранённые дата и время посадки её группы в МСК
минус один час. Время из текста сообщения или запроса браузера не используется.
Ровно в момент срока отправка уже запрещена. Просроченные адресаты исключаются
из нового запуска; срок повторно проверяется worker до и после проверки канала.
Экстренный режим обходит только рабочее окно, но не срок. Изменение расписания
после постановки в очередь не меняет уже подтверждённый снимок сообщения.

При недоступности канала worker оставляет задание в очереди и проверяет позже
(до пяти минут, не позднее срока). После срока доставка становится `skipped`
с причиной. Исторические уведомления получают срок из структурированных даты
и времени payload; если срок невозможно определить, отправка пропускается.
Свободные рассылки без времени посадки не получают этот срок.

`accepted` означает только приём запроса провайдером, не доставку. Уже переданные
сообщения могут доставиться после срока: у локальной очереди нет гарантии
отмены сообщения внутри Green API. При неопределённом результате POST повтор
не выполняется автоматически. Строки `sending` после аварийной остановки
также не захватываются повторно: нужен разбор оператором, чтобы избежать дубля.

Обычное чтение групп и очереди не обращается к провайдеру. Значения внешней
очереди отображаются как неизвестные; показываются реальные локальные состояния.
Бейдж использует только свежий сохранённый снимок, а явная проверка подключения
свободной рассылки сохраняет прежнюю проверку. Сессия API освобождается после
проверки CSRF, чтобы долгий запрос канала не блокировал остальные запросы пользователя.

## Проверка

- `./scripts/preflight.sh` — общий набор, включая 38 проверок срока и очереди.
- `tests/notification_offline_ui_test.cjs` с Playwright — реальный интерфейс
  на синтетическом локальном сервере, экраны 1360/390, внешний трафик запрещён.
- Для полного выпуска необходимы серверная репетиция, проверенный main,
  актуальная копия и допуск схемы/фоновых заданий по `release-readiness.md`.

RULE-01/03/06/07/11/14/15; RISK-001/003/004/008/009/013/014. Тесты не являются
подтверждением выпуска или успешной доставки через реального провайдера.
Новая миграция этой правкой не добавляется; при обновлении старого рабочего
выпуска на текущий main остаются требования schema30 и BackgroundJobs.
