# Исправление хранения сессий и репетиция восстановления

Дата: 05.10.2026, Europe/Belgrade. Задачи #43/#44, журнал #35.
RULE-04/11/15; RISK-003/006/013. Проверки выполнения приложения также затрагивают
RISK-001/004/008, но не закрывают исторические риски целиком.

## Выполнено на рабочей среде

Настройки PHP и системной очистки согласованы с уже принятой в приложении
политикой хранения сессии. Исходная конфигурация сохранена с ограниченным
доступом. Проверена конфигурация, выполнено плавное перечитывание PHP.
Путь хранения и действующие сессии пользователей не менялись.

Через работающий FPM проверены срок хранения и защитные атрибуты cookie.
Искусственная неавторизованная сессия сохранила значение после 12,4 минуты
без запросов и одного штатного запуска системной очистки. Этот интервал
короче прежнего срока истечения и сам по себе не доказывает длительное хранение.

Отдельный тест PHP `session_gc` с искусственным временем файла подтвердил:
часовая сессия сохраняется, сессия старше 31 дня удаляется. Это проверка механизма
старения в изолированном каталоге, а не ожидание 31 дня и не выполнение очистки
над пользовательскими сессиями. Возврат конфигурации проверен распаковкой
исходной копии и чтением её параметров; рабочая настройка обратно не менялась.

После проверки завершена только созданная тестом сессия, временный обработчик
убран из доступа FPM. HTTPS-вход и службы работают. Все 208 присутствующих
версионируемых файлов рабочего приложения по-прежнему совпадают с
`02f31c2ae0fa08f5ae418aaa3e7003ad27a2d38e`.

## Копия и восстановление

Созданы транзакционная копия БД и архивы приложения, рабочих файлов, необходимых
настроек и TLS-конфигурации. Учтены каталоги за пределами дерева приложения.
Хеши рабочих файлов до и после копирования совпали; остановка рабочего приложения
не выполнялась. Это наблюдаемая стабильность по двум сверкам, а не атомарный
снимок всех дисков. Все таблицы проверенной БД используют транзакционный движок.

В отдельный экземпляр БД восстановлена копия; каноническая повторная выгрузка
побайтово совпала с исходной. Файлы рабочих хранилищ проверены по манифесту,
распакованные код/настройки/TLS и симлинки — по содержимому архивов.

Изоляция подтверждена отдельным каталогом/сокетом БД, отсутствием внешних сетевых
интерфейсов и проверкой фактического каталога подключённой БД до пишущих тестов.
Для приложения использован отдельный FPM; внешние провайдеры и фоновые отправки
не запускались. Копии и секреты остались в закрытом серверном каталоге,
в репозиторий внесён только этот отчёт. Данная копия находится на том же сервере
и не заменяет резервирование на случай потери всего сервера.

## Проверки приложения

Проверены три последовательные конфигурации:

| Код в изолированной среде | Успешные проверки |
| --- | ---: |
| Предыдущий `02f31c2` | 32 |
| Кандидат `ea4bdda` | 61 |
| Возврат к `02f31c2` | 34 |

Это число проверенных утверждений, включая повторные проверки ответов,
а не число независимых пользовательских сценариев.

Использован штатный вход искусственного администратора в восстановленной БД.
Проверены перенаправление без входа, отказ неверному CSRF с фактическим кодом
приложения 419, смена session ID, загрузка главной страницы, чатов, ведомостей,
контактов, отчётности и настроек. После выхода старый session ID не даёт доступа.

В кандидате дополнительно проверены `no-store`, постоянство ключа рабочего
контекста между страницами, новый ключ после повторного входа, отсутствие
ключа без входа и разделение по пользователю, ответ 404 для недоступных объектов.
Проверки серверных ответов выполнены через FastCGI; браузерный JavaScript
этой репетицией не исполнялся. Его отдельные изолированные тесты описаны в
[отчёте рабочего места](workspace-restore.md).

При работе кандидата в копии созданы синтетические запись и файл. После
возврата предыдущего кода оба сохранились: старый дамп поверх базы не применялся.
Это подтверждает совместимость кода в восстановленном окружении; не является
репетицией переключения nginx, активных запросов или очереди внешнего провайдера.

## Ограничения и следующий допуск

- Кандидат приложения на рабочий сайт не установлен.
- Новая проверка реальной авторизации оператора и отзыва прав не выполнялась.
- Естественный длительный простой не проверен; модель старения описана выше.
- Живое переключение каталога, OPcache при переключении, активные запросы,
  фоновые задания и повторы входящих событий требуют отдельной репетиции до
  выпуска. Поэтому #44 и общая подготовка #42 пока не закрываются.
- Изолированная БД остановлена, закрытые копии и результаты сохранены.

Уточнение RULE-15: проверять состав копии, техническую изоляцию и сохранение
новых данных при возврате кода; не смешивать результат восстановления с
готовностью переключения действующего сайта.
