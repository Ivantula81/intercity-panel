# Сохранение полей и черновики диалогов — этап 1

Задача #38, журнал #35. Дата проверки: 29.09.2026.
Основа ветки: `526b998062b21b7be7bb2be943657c0aca091e24`.

## Область изменения

Ячейки редактора ведомости: данные рейса и пассажиров. Статус отражает
ожидание, выполнение, подтверждённое сохранение и отказ. Один запрос на поле
выполняется за раз; ввод во время запроса остаётся новой версией. Ошибка
одного поля не скрывается успехом другого; доступен явный повтор.

В чате черновик привязан к ID диалога. Этот серверный ID различает канал,
учётную запись канала и внешний диалог (`schema15.sql`). Отправка фиксирует
ID и версию текста до ожидания ответа. Поздний успех очищает только исходную
неизменённую версию. Ошибка остаётся у исходного диалога. Автоматического
повтора отправки нет; при потере ответа предлагается проверить историю.
Ограничение одной одновременной отправки на открытой странице сохранено.

Общий обработчик полей вызывает специализированный обработчик раздела
рассылок, когда этот модуль загружен. Его существующая последовательность
сохранения перед подготовкой отправки сохраняется и проверена отдельно.
Это не переделка всех редакторов и форм приложения.

Черновики существуют только в памяти открытой страницы. При незавершённом
вводе запрашивается штатное предупреждение браузера перед уходом.
Постоянное хранение и восстановление после переходов/перезапуска — следующий
этап. Предупреждение браузера не является надёжным хранилищем и может не
показаться при завершении процесса или на отдельных мобильных браузерах.

## Воспроизведение

Нужны PHP с PDO SQLite, Node.js, Playwright и Chromium/Chrome.
Из корня репозитория:

```sh
./scripts/preflight.sh
node tests/save_draft_ui_test.cjs
```

Если браузер не установлен через Playwright, передать его путь в `CHROME_PATH`.
Для отдельной установки модулей Node использовать `NODE_PATH`.
Необязательный `SAVE_DRAFT_SCREENSHOT_DIR` сохраняет мобильные снимки.
Сценарий запускает временный HTTP-сервер на loopback и случайном порту,
рендерит настоящие PHP-представления на вымышленных данных и загружает
настоящие JS/CSS. PHP-фикстура доступна только через CLI.
API перехватывается полностью, внешние запросы запрещены. Проверка записи
с последующим чтением использует искусственное хранилище, не рабочую БД.

## Результаты

- Штатный preflight успешен: синтаксис PHP/JS, проверки diff и профильные
  наборы уведомлений, диалогов, расписаний, продаж и финансовых расчётов.
- 15 групп браузерных проверок успешны; ошибок JavaScript: 0.
  Машиночитаемый список: [save-draft-result.json](save-draft-result.json).
- Успех и повторное чтение; отказ приложения, потеря сети, истечение входа,
  некорректный JSON и пустой ответ; сохранность текста и повтор с клавиатуры.
- Последовательность записей одного поля, промежуточный ввод, независимые
  поля с ответами в обратном порядке, ошибка рядом с успешной записью.
- Настоящий обработчик рассылок: отказ сохраняет ожидающие изменения;
  повторная запись завершает ожидание перед подготовкой.
- A/B/A и закрытие диалога; новый ввод и переключение во время отправки;
  двойной клик, явный повтор, таймаут без автоматической повторной отправки.
- Устаревший успешный/ошибочный ответ истории, обратный порядок фоновых
  ответов и загрузка дольше интервала опроса; сбой отметки прочтения.
- Desktop 1360 px и узкий экран 390 px; Enter/Shift+Enter, фокус, доступное
  имя поля сообщения, кнопка повтора не меньше 44 px, reduced motion.
  Мобильные снимки просмотрены.
