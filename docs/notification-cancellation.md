# Остановка отправки уведомлений

Кнопка «Остановить отправку» находится в раскрытой очереди уведомлений рядом
с конкретным запуском. Остановка действует сразу, без дополнительного диалога.
Она относится ко всему выбранному запуску; другие запуски продолжают работать.

После остановки:

- ожидающие передачи сообщения получают статус «Остановлено»;
- начатые запросы остаются «В обработке» до появления результата;
- принятые провайдером, доставленные и прочитанные сообщения сохраняют статус;
- неопределённый ответ на отправку остаётся ошибкой, а не подтверждением отмены.

Уже переданный провайдеру запрос отозвать этой кнопкой нельзя. Финальная
проверка остановки выполняется непосредственно перед передачей; запрос,
начавшийся одновременно с нажатием, может завершиться после подтверждения
остановки. Общая внешняя очередь аккаунта не очищается.

После исправления автобуса/водителя нужно открыть «Подготовить / дослать»:
неотправленные получатели снова доступны для нового запуска с актуальным
текстом. Прежний запуск не возобновляется. Для пассажиров, уже получивших старый
текст, используется отдельное «Отправить исправление». Снимки прежних текстов
остаются в истории. Неопределённые результаты требуют проверки перед повтором.

## Контракт

`POST notification.cancel`: ровно одно из `run_id` / `job_id`, положительное
целое. Задание, связанное с запуском, останавливает весь запуск. Разрешены
существующие роли `admin` и `operator`; действуют вход и общая проверка CSRF.
Успех записывается в аудит с исполнителем и идентификатором сущности.

Повтор запроса безопасен. Ответ содержит количества `stopped`, `sending`,
`transferred`, `failed` на момент остановки, а не гарантию окончательной доставки.
При ошибке интерфейс сообщает, что остановка не подтверждена, и разрешает повтор.
Медленная диагностика внешней очереди не задерживает локальную кнопку.

Используются существующие состояния schema24: `broadcast_jobs.cancelled` и
`broadcast_deliveries.skipped` с причиной остановки. Отдельной миграции нет.
Остановка, создание доставок и завершение worker согласованы транзакциями с
порядком блокировок «задание → доставки». Worker не возвращает отменённое
задание в работу; очередной повтор проверки связи также отменяется.
Неопределённые ответы POST не повторяются автоматически, включая свободные
рассылки старого формата: иначе отмена могла бы ошибочно назвать такой повтор
«не переданным», хотя первое сообщение уже принято провайдером.

Остановка не закрывает остальные риски выпуска. Полный main включает ранее
принятую schema30; если её нет на рабочем сервере, требуется отдельный допуск
миграции согласно AGENTS.md. Наличие кнопки в ветке не означает внедрение.

## Проверка

- `./scripts/preflight.sh`, включая `tests/notification_cancel_test.php`:
  повтор, частичная передача, отмена во время проверки связи, поздний ответ,
  запрет повторной постановки, отказ хранилища и атомарность всего запуска.
- `node tests/notification_cancel_ui_test.cjs`: 1360/390, медленный провайдер,
  ошибка API, повтор и двойной клик, отдельные запуски, обновление страницы.
- `node tests/notification_offline_ui_test.cjs`: подготовка, подтверждение,
  неизменный ключ повторного запроса и срок отправки.
- `tests/notification_cancel_mysql_test.php`: только отдельная MariaDB в
  изолированном сетевом пространстве с явным подтверждением тестового datadir;
  конкурентные stop/claim/finish/retry и настоящий worker без внешней сети.
- Перед выпуском — реальный API/FPM на восстановленной копии: вход, роли,
  CSRF, неверный метод/объект, неизменность при отказе, аудит, история и откат.
