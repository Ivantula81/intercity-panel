# Журнал действий и решений

Постоянная точка входа: [GitHub issue #35](https://github.com/Ivantula81/intercity-panel/issues/35).

Правило введено 23.09.2026 по указанию владельца. Журнал служит общей памятью
проекта и остаётся открытым после завершения отдельных задач.

## Перед работой

1. Прочитать журнал, последние комментарии, связанные задачи и PR.
2. Прочитать AGENTS.md и действующий реестр рисков.
3. Сверить актуальную версию, состояние затронутых задач и незавершённые изменения.
4. Записать цель следующего действия, ожидаемый результат и способ проверки.

## После каждого содержательного действия

Добавить запись в issue. Не откладывать весь журнал до конца большой задачи.
Отдельно фиксировать изучение источников, проверку гипотезы, выводы анализа,
изменение документа или кода, результат проверки, публикацию PR и выпуск.
Связанные мелкие операции одного действия можно описать в одной записи.

Шаблон:

```text
Дата и время (с часовым поясом):
ID записи:
Тип: исследование / гипотеза / предложение / решение / изменение / проверка / выпуск
Цель:
Действие:
Результат:
Подтверждение: ссылка на публичный источник, задачу, commit, PR или проверку
Затронутые процессы и RISK-ID (если применимо):
Ограничения и что не проверено:
Следующий шаг:
```

## Идеи и решения

- Новую идею записать с причиной, ожидаемой пользой, альтернативами и способом проверки.
- Вопрос снабдить контекстом: что зависит от ответа и можно ли продолжать другую работу.
- Факт отделять от гипотезы; предложение — от решения владельца.
- Решение сопровождать датой и основанием: прямое указание владельца или выбор в пределах уже согласованного объёма.
- Изменение вывода оформлять новой записью со ссылкой на прежнюю, сохраняя историю.
- Не обозначать написанный код как проверенный или выпущенный без соответствующих подтверждений.

## Связь с изменениями

Ссылаться на журнал из PR. В журнале сохранять обратную ссылку, выполненные
проверки и остающиеся ограничения. Задачи реализации закрывать по их критериям
готовности; этот issue не закрывать автоматически через `Closes #35`.

## Публичность и доступность

Репозиторий публичный. Записи должны быть пригодны для публичного размещения.
Не публиковать персональные данные, секреты, внутренние показатели бизнеса,
реальные сообщения, закрытые документы и подробности незакрытых уязвимостей.
Для непубличного материала указывать лишь нейтральный факт существования
закрытого приложения, без раскрывающих подробностей и закрытых ссылок.

Если GitHub недоступен, сохранить датированную запись локально с пометкой
«ожидает синхронизации», сообщить об этом и перенести её после восстановления
доступа. До переноса не утверждать, что действие записано в GitHub.
