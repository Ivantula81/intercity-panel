# Ревью раздела «Уведомления» — 2026-07-07 (Claude)

**Формат:** только оценка, без правок кода (по требованию владельца). Смотрели текущее состояние
после рефакторинга Codex «по направлениям» (ветки `codex/notification-*`).

Файлы: `app/views/notifications.php`, `public/assets/panel.js`
(`loadGroups`/`renderGroups`/`renderPreparationSummary`/`sendAllGroups`/`loadCampaignOverview`).

## Как сейчас устроен экран (сверху вниз)

1. Шапка: заголовок + подпись «загрузка → проверка данных → группы → отправка» + ↺Сбросить / 🗑Удалить / статус канала.
2. Плашка «WhatsApp — основной канал…».
3. **ШАГ 1 — Ведомость** (загрузка CSV / выбор ранее загруженной).
4. **ШАГ 2 — Данные рейса** (дата/время, автобус, телефон водителя, доп.инфо, «Обновить времена из GDS», галочки фото/телефон) **+ панель «Каналы отправки»** (WhatsApp/MAX/Telegram/SMS + оценка числа сообщений).
5. **ШАГ 3 — Подготовка рассылки**:
   - блок готовности (заголовок + кнопка **«Отправить N пассажирам»** + метрики: пассажиров/направлений/WhatsApp/требует внимания);
   - блок «Требует внимания» (до 12 проблем, у каждой кнопка «Открыть»);
   - **список групп: направления двухуровнево** — секция по станции отправления → внутри карточки по каждому пункту назначения (`gcard`). В каждой карточке: дата, время, выбор шаблона, textarea текста, предпросмотр, `details` «Получатели» (чекбоксы + правка телефона + бейджи каналов + «+ Добавить»), кнопки **«Отправить этой группе»** и «↺ Сбросить к шаблону».
6. **ШАГ 4 — Отправка** (ещё раз сводка + кнопка **«Подтвердить и отправить»**).
7. **Единый монитор доставки** (метрики доставки + «Нужно действие» + `details` со всеми получателями).

## Корневая проблема — направление сделано главной единицей навигации

Codex технически прав: сообщения **должны** быть изолированы по точной паре «откуда → куда»
(у каждой станции своё время и адрес посадки — это фикс `schema16.sql`, без него смешивались времена).

Но **изоляцию данных** он превратил в **изоляцию интерфейса**: один рейс распадается на
N секций × M карточек. Для рейса Москва→Крым с 5 посадками и 6 точками высадки это до ~30 карточек
на одном экране. Оператор вынужден думать не «один рейс, разослать всем», а «десятки направлений,
каждое отдельно». Отсюда ощущение «сложно и много действий».

## Где именно много действий

- **Дублирование управления в каждой карточке.** Дата, время, шаблон, текст, предпросмотр, «отправить»,
  «сбросить» повторяются в КАЖДОМ направлении. Хочешь поправить формулировку — правишь в N карточках
  (если не спасает общий шаблон).
- **Три уровня отправки одновременно.** Глобально «Отправить N пассажирам» / «Подтвердить и отправить»
  (обе → `sendAllGroups`), плюс «Отправить этой группе» в каждой карточке (`sendGroup`), плюс «дослать»
  по каждому получателю в мониторе. Непонятно, чем пользоваться.
- **Кнопка отправки на экране дважды.** `notificationReadiness` и `send-bar` — обе `data-send-all`,
  делают одно и то же, видны одновременно.
- **Две разные «Требует внимания».** До отправки (плохие телефоны/нет времени/нет адреса/нет мессенджера)
  и после отправки («Нужно действие» в мониторе) — похожая вёрстка, разный смысл, надо различать.
- **Каналы отправки оторваны от кнопки.** Выбор канала — в ШАГ 2, кнопка отправки — в ШАГ 3/4.
  Сменить канал перед отправкой = проскроллить вверх, переключить, вернуться вниз.
- **Постоянные автопроверки/перерисовки.** `autoCheckManifestChannels` срабатывает на загрузке, при правке
  телефона, при переключении канала → мигает «проверяю…», блок готовности перерисовывается. Экран «дёргается».
- **Много вложенных раскрывашек.** Карточка сворачивается, внутри `details` «Получатели», в мониторе ещё
  `details`, в обзоре ещё `details` — чтобы увидеть детали, кликаешь вглубь на 2–3 уровня.

## Что при этом работает нормально (честно)

- **Счастливый путь короткий:** загрузил CSV → времена подтянулись из GDS → глянул готовность →
  «Отправить N пассажирам» → подтверждение. Это ~2–3 клика. Проблема не в длине пути, а в визуальной
  плотности и в том, что любая правка/исключение заставляют «нырять» по карточкам.
- Разделение по паре «откуда→куда» на уровне данных — **правильное**, ломать его нельзя.
- Сбор проблем в один список и монитор доставки с автообновлением статусов — полезные идеи сами по себе.

## Куда двигать (НЕ реализуем сейчас — только направление)

1. **Свернуть направления по умолчанию.** Главный вид — «один рейс, N пассажиров, разослать всем».
   Карточки направлений — за раскрывашкой «раскрыть для точечной правки» (подпись это уже обещает,
   но карточки показаны развёрнуто).
2. **Одна кнопка отправки** (убрать дубль readiness/send-bar).
3. **Каналы — рядом с кнопкой отправки**, а не в «Данных рейса».
4. **Слить блок готовности и предотправочный «Требует внимания»** в один; монитор после отправки — отдельно.
5. Отправка по одной группе — вторичное действие внутри раскрытого направления, а не равноправная третья кнопка.

**Вывод:** данные разложены верно, но интерфейс навязывает оператору «мышление направлениями».
Нужно вернуть на первый план сущность «рейс/рассылка», а направления спрятать до момента точечной правки.
